## 1. Ce que ce protocole mesure

Un **troisième usage local, sans boucle d'outils** : quand une sortie de tests est longue, un modèle local la résume **en un seul appel** (point d'accès compatible OpenAI, adresse de boucle locale uniquement, sans outil) avant que le texte parte au cloud. C'est un prétraitement non privilégié (FOUNDRY-ADR-0007). La question est celle de la v5 pour un autre usage : **le résumé du candidat retenu laisse-t-il au modèle cloud la même capacité de diagnostic, pour moins de tokens premium par diagnostic juste ?** Ce que le protocole ne mesure pas : une livraison Foundry complète (limite L7).

## 3. La matière

**Production** (verbe hors ligne `compression-material`, sans cloud, sans modèle, sans `claude`) : pour chacune des 12 tâches, un bundle du **code de base non modifié** (celui de tout bras : l'arbre de base sans les tests protégés, dans un dépôt neuf), puis les tests protégés restaurés depuis le commit fusionné et lancés par **le juge lui-même** (`lfc.judge`, avec son interpréteur `sys.executable`, sa commande et son environnement ; `judge` n'a gagné qu'un paramètre `capture` qui rend la sortie, inactif par défaut). La sortie complète — stdout, puis stderr sous la ligne `--- stderr ---` s'il y en a (aucune tâche n'en a produit) — est versée telle que le juge l'a vue, **après masquage exact** : le dossier du bundle → `<bundle>`, le dossier temporaire du juge → `<tmp>`, le dossier personnel → `<home>`, le nom d'utilisateur → `<user>`. Les chemins masqués sont comptés par tâche dans l'index (tableau ci-dessous). Le générateur **refuse** la matière si un chemin personnel ou un nom d'utilisateur reste, si le nombre d'identifiants analysés diffère des comptes junit du même run, ou s'il n'y a aucun test en échec ; un test contrôle les fichiers versés (aucun chemin personnel, aucun nom d'utilisateur, aucune chaîne en forme de secret). Les sorties contiennent du code de test du dépôt (traces) : elles montrent aux bras de diagnostic des tests protégés que les bras d'implémentation des v1 à v5 ne voient jamais (limite L7).

Empreintes, tailles et lignes : [`pat-19-compression-material-v1.json`](pat-19-compression-material-v1.json) (son sha256 est épinglé dans les deux configurations ; le chargeur vérifie l'index et chaque texte, et que les identifiants analysés du texte sont ceux de l'index). **Estimation en tokens : inconnue** — aucun décompte exact d'un tokenizer local n'a été fait (aucun modèle n'est lancé par ce brouillon) ; le champ vaut `null`.

## 4. L'appel local

Exactement un appel `POST` Chat Completions non diffusé, sans outil (le corps ne contient que `model`, `messages`, `temperature`, `max_tokens`, `stream: false`), au point d'accès de `compression.local_call.endpoint` : une URL `http` sur une **adresse de boucle locale littérale** avec port (le chargeur refuse tout autre hôte, un nom, des identifiants dans l'URL, un autre schéma ; aucun proxy n'est utilisé). Le modèle demandé est la clé LM Studio du candidat. Messages : un système figé, puis la consigne figée où `{output}` est la sortie complète (committée, masquée) et `{budget}` la taille demandée. Réponse : le `content` brut est le résumé (aucun nettoyage : un bloc de raisonnement éventuel dans le contenu compte dans la taille). Cas : délai dépassé → `timeout` ; statut HTTP non 200 → `http_<statut>` ; réponse qui n'est pas une réponse Chat Completions → `invalid_answer` ; contenu vide → `empty_answer` ; coupure pendant la réponse → `connection_lost` ; tous sont des **résumés en échec** (rappel 0, jamais rejoués, raison consignée). Un point d'accès où rien n'écoute est un échec d'instrument, pas un échec du candidat : tentative nulle (`tool_error`), rejouée une fois. Aucun appel n'est fait par le lanceur hors de ce chemin ; le lanceur ne charge aucun modèle.

## 5. Le tamis local (sans cloud)

Pour chaque (candidat, tâche) : préflight de machine dédiée, un appel, jugement **sans modèle** (`score_summary`) :

- **rappel** = identifiants en échec cités tel quel dans le résumé / identifiants en échec ; **taille** = octets du résumé / octets de la sortie ;
- un candidat **passe** si (i) son rappel moyen sur les 12 tâches est ≥ 0,8 (comparaison exacte en fractions ; 0,8 exactement passe) **et** (ii) **chaque** résumé produit fait au plus 25 % de **sa** sortie (25 % exactement passe) ; un résumé en échec compte 0 pour (i) et n'est pas jugé pour (ii) ;
- **sélection** : section 2, C4. **Arrêt** : aucun candidat ne passe → `stop: keep_cloud`, **aucune comparaison**, résultat conforme (PAT-ADR-0015) ; le lanceur refuse alors toute comparaison ;
- la sélection n'est faite que lorsque les cinq candidats ont un verdict sur les 12 tâches et qu'aucune tentative n'est restée coupée ; le pilote n'a **pas** de sélection (un candidat sur une tâche : le candidat est celui de l'opérateur).

## 6. La comparaison aval

**Bras.** F : la sortie complète. S : le résumé du candidat retenu, lu dans son enregistrement de tamis (la comparaison ne charge **aucun** modèle). Un diagnostic par (tâche, bras), une exécution cloud, Sonnet 5.5, effort `medium`, sous l'instrument de la v5 : bac à sable Bash natif de Claude Code, mode `dontAsk`, bundles sans `.claude`, audit révision 2 et politique `journal_under_observed_barrier`, racine privée par tentative, lecture du seul fichier `.config/git/ignore` du home. Le bras reçoit l'énoncé de la tâche (le même que tous les bras, plus le pied de page `statement_footer`) et la sortie dans la consigne ; il doit répondre par un objet JSON `{"file": "...", "function": "..."}`, dernier message. **Si la sortie du tamis du candidat retenu est en échec pour une tâche, le bras S n'est pas joué sur elle** (rien à envoyer) : la tâche est indécidée pour S.

**Outils (liste proposée et ce qui est vérifié).** Lecture seule : l'argv est celui de l'implémenteur v5 avec `Edit` et `Write` ajoutés aux outils refusés (comme l'explorateur cloud des v2 et v3 ; le chargeur le vérifie), `Bash` reste disponible sous le bac à sable natif (la recherche de l'hôte passe par lui : l'explorateur cloud de la v2 listait exactement `Bash` et `Read`), et **le bundle entier est protégé en écriture** par les réglages passés (`denyWrite` pour le shell, règles de refus `Edit`/`Write` sur le bundle ; les autres rôles ne protègent que leur `.claude`). La liste `allowed_tools` (`Bash`, `Glob`, `Grep`, `Read`) est la liste d'autorisation de l'événement `init` : un outil hors liste refuse l'enregistrement. Le lanceur compare aussi `git status` du bundle avant et après : un bundle modifié refuse le diagnostic (diagnostic faux, coût compté). **Vérifié par les tests** (bras factices) : drapeaux, réglages, refus, comparaison de l'état du bundle, environnement de R6 transmis tel quel, `claude` jamais enveloppé. **Non vérifié, à établir par le pilote** : que Claude Code 2.1.294 accepte cet argv, que `Edit`/`Write` sont bien absents de l'événement `init`, que le shell ne peut pas écrire dans le bundle, que `Read` du bundle fonctionne sous `dontAsk`, que la réponse JSON se lit dans le message final.

**Vérité terrain.** [`pat-19-exploration-truth-v2.json`](pat-19-exploration-truth-v2.json) (sha256 épinglé comme en v5). Un diagnostic est **juste** (C8) ; une réponse illisible ou absente est **fausse**, son coût compté ; un enregistrement `contaminated` (le bras a touché un chemin sensible ou lancé une commande interdite) est **indécidé**, jamais faux.

**Ordre de lecture écrit d'avance** (`apply_rule`). D = ensemble des tâches **décidées dans les deux bras** (un bras est décidé quand un enregistrement porte un verdict de diagnostic, juste ou faux). Dans cet ordre :

1. moins de **9** tâches dans D (1 pour le pilote) : `inconclusive` ;
2. un total de tokens premium inconnu sur une tâche de D : `inconclusive` (jamais zéro) ;
3. justes(S) < justes(F) sur D : `keep_cloud` ;
4. justes(F) = 0 : `inconclusive` (le rapport est indéfini ; aussi quand justes(S) > 0) ;
5. tokens premium par diagnostic juste : S ≤ 0,85 × F (comparaison exacte en fractions, égalité incluse) → `retained`, sinon `keep_cloud` ;
6. un `retained` doit aussi tenir **dans le pire cas sur les 12 tâches** (les tâches indécidées de S comptées fausses, celles de F justes) ; sinon `inconclusive` ;
7. enfin, les **raisons de campagne** donnent `inconclusive` quelle que soit la lecture de D : une exécution cloud démarrée au registre et jamais soldée, une qu'aucun enregistrement ne nomme, une interrompue ou aux tokens illisibles qui appartient à une tâche de D ou à aucune tâche, un départ au registre sans enregistrement ni rejeu.

Tâches indécidées (contaminée, erreur d'outil, interruption, plafond, résumé absent) : elles **quittent D** ; leur coût est imprimé à part. Une tâche **coupée par le plafond n'est jamais rejouée** ; une erreur d'outil ou une interruption avant tout verdict l'est **une fois**. **Minimum de 9 tâches décidées de 12** (celui de la v5, 75 %) : moins, la campagne est `inconclusive` ; ce n'est pas une valeur validée par le mainteneur. `retained` = cette compression, avec ce candidat, vaut le coup pour cet usage ; **aucune promotion dans aucun cas** (PAT-ADR-0015) ; un résultat ni `retained` ni `keep_cloud` sur une campagne complète conclut `keep_cloud_insufficient_evidence`.

## 7. Lectures non décisionnelles à préenregistrer (hors règle)

- **Lecture pondérée du rapport S/F** avec l'outil et la grille de PAT-129 (`python3 -m foundry.cost_breakdown --results … --report …`, [`pat-19-cost-breakdown-v1.md`](pat-19-cost-breakdown-v1.md)) : poids de prix de liste d'API, jamais une facture. L'outil lit les enregistrements `F` et `S` (rôle `diagnoser`), donne le rapport des totaux sur les tâches communes et, avec le rapport de la campagne, le rapport **par diagnostic juste sur D** pondéré (`paired_reading`, clés `weighted_ratio_S_over_F_per_correct`). Elle ne change aucun verdict. PAT-129 a montré que, pondéré, le coût est dominé par les écritures de cache, les tokens de sortie et le relecteur Opus : ici il n'y a pas de relecteur et la sortie est courte, mais ce n'est pas mesuré.
- **Tableau des tailles** : octets des sorties (section 3) et, par candidat, octets des résumés (`compression_sizes` du rapport).
- Durée et état de la machine des appels locaux (déjà dans les enregistrements) : le coût du **tamis local n'entre pas** dans la règle (les tokens locaux ne sont pas premium).

## 9. Préalables et pilote

**Préalables.** Sauvegarder, hors du dépôt, l'état Foundry aux deux emplacements du registre ([`pat-19-v3-operator.md`](pat-19-v3-operator.md), « Avant une campagne ») ; machine dédiée ; serveur LM Studio démarré sur l'adresse de boucle locale de la configuration ; enveloppe écrite par l'opérateur dans un dossier d'exécution propre à chaque mode (voir [`pat-19-c1-operator.md`](pat-19-c1-operator.md)).

**Critères d'arrêt écrits avant le pilote.** L'instrument n'est **pas** utilisable si l'un des cas suivants se produit (le coordinateur décide en lisant les transcriptions) : (a) un enregistrement est écarté par l'instrument et non par la conduite du bras (un signalement dont la transcription montre que le bras est resté dans sa tentative) ; (b) le bras cloud ne peut pas lire son bundle ou rendre son JSON à cause du mode de permission ou du bac à sable ; (c) la valeur de `audit.barrier` n'est pas `settings_transmitted_version_observed` pour un enregistrement mené à son terme ; (d) le `registry.json` réel de Foundry change ; (e) l'appel local ne peut pas être fait, ou sa réponse est refusée pour une raison d'instrument (connexion refusée, requête rejetée alors qu'elle est bien formée, contenu vide parce que la réponse tient dans un autre champ, `finish_reason` `length` sans contenu) ; (f) le juge ne peut pas analyser la matière (identifiants illisibles, matière refusée au chargement) ; (g) **ajouté par l'implémenteur, absent de la liste du coordinateur** : le bras a pu écrire dans son bundle, ou l'événement `init` liste un outil hors de `allowed_tools` (enregistrement refusé). Le pilote ne règle aucune valeur de la règle de décision ; tout changement d'instrument qu'il provoque est listé dans ce protocole **avant** le gel.

**Ce que le pilote regarde aussi** (sans critère d'arrêt) : `finish_reason`, `usage` et la présence d'un bloc de raisonnement dans le contenu de l'appel local ; les outils de l'événement `init` du diagnostic ; les tentatives d'écriture refusées ; l'écho du `git` ; le coût du diagnostic F contre S sur une seule tâche (**ne vaut pas résultat**).

## 10. Limites

- **L1 — Douze tâches déjà vues, non indépendantes.** Les 12 tâches ont déjà servi aux v2 à v5 ; 9 modifient `tests/test_linear_tracker.py` ; la branche empilée des PR 24 à 27 met quatre tâches l'une sur l'autre ([v4, section 5](pat-19-protocol-v4.md)). Douze observations, pas douze mesures indépendantes. La PR 27 est la tâche du pilote.
- **L2 — Une seule exécution** par (tâche, bras) et par appel local : pas de répétition, pas d'estimation de la variance du modèle local (température 0 ne rend pas la sortie déterministe sur toutes les piles) ni du modèle cloud.
- **L3 — Pas d'outil dans l'appel local** : le modèle ne peut rien lire d'autre que la sortie ; ce n'est pas un agent.
- **L4 — Les identifiants doivent figurer tels quels.** Un résumé qui cite `test_added` sans son chemin ou son nœud paramétré ne compte pas ; l'exigence mesure autant la fidélité de copie que la compréhension. Un nœud dont l'identifiant contient ` - ` serait coupé par l'analyseur (le générateur le détecte par le compte junit).
- **L5 — Diagnostic jugé sur un fichier et une fonction.** Une cause qui touche plusieurs fonctions, ou une fonction hors du produit, n'est jugée que sur celle nommée ; la vérité terrain est celle du diff fusionné.
- **L6 — Pas de lecture de la qualité d'un correctif** : le protocole ne demande pas de corriger ; il mesure une étape de diagnostic synthétique.
- **L7 — Ce n'est pas une livraison Foundry.** Le bundle des bras de diagnostic est celui des autres bras (tests protégés retirés ou, pour les tests ajoutés, absents), alors que la sortie en cite le code ; en usage réel le modèle verrait les tests. Les bras de diagnostic voient du code de test protégé (dans la sortie) que les bras d'implémentation ne voient jamais.
- **L8 — Règle sur les tokens premium non pondérés**, sommés sur D puis rapportés au nombre de diagnostics justes : **dominée par les plus grosses sorties** (la PR 48 porte 71,8 % des octets). Le rapport pondéré par prix (section 7) est donné à part, hors règle. Les tokens **locaux** (appel au modèle local) ne sont pas premium et ne comptent pas : le bras S ne paie pas son résumé dans la règle.
- **L9 — Un chargement par candidat** (C5) : l'état du modèle chargé au fil de 12 appels n'est pas contrôlé ; aucun écart n'est établi, aucun n'est exclu.
- **L10 — Contexte.** La PR 48 dépasse très probablement le contexte déclaré (section 3) ; les contextes réellement chargés peuvent différer de `min_context` (le préflight exige au moins `min_context`).
- **L11 — Héritées de la v5 sans changement** : dossier temporaire partagé (`TMPDIR` ne peut pas être changé, R6), sur-signalements de l'audit révision 2, comportement des bras sous `dontAsk`, Claude Code 2.1.294 jamais exercé (C11), l'effet de chaque changement d'instrument pris seul non mesuré.
- **L12 — Sorties de tests copiées de l'arbre de travail** : la matière est produite sur une pile (Python, pytest, système) enregistrée dans l'index ; elle n'est pas rejouable octet pour octet.

## 11. Ce que ce brouillon ne dit pas

- Aucun résultat : rien n'a tourné contre un modèle ; les chiffres ci-dessus sont des tailles de fichiers et des comptes de tests, rien de plus.
- Que `claude` 2.1.294 accepte l'argv du bras de diagnostic, que le bundle y est réellement en lecture seule, que les cinq candidats se chargent avec leur commande épinglée sur cette machine aujourd'hui, que le serveur LM Studio répond sur l'adresse de la configuration : **inconnu**, c'est l'objet du pilote.
- Qu'un prompt de 425 688 octets (le bras F sur la PR 48) passe comme argument de `claude -p` : le système accepte un argument de cette taille (limite totale 1 048 576 octets, mesurée avec `echo`), mais Claude Code n'a jamais été essayé ainsi ; le pilote joue la PR 27 (3 854 octets) et ne peut pas le montrer. Le contexte de Sonnet 5.5 et le coût d'une telle entrée sont **inconnus**.
- Qu'un seul candidat atteindra 0,8 : inconnu. Qu'une compression soit utile quand la plupart des sorties sont petites : non établi.
